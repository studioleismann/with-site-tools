# Development and build

## Commands

```bash
npm start
npm run build
npm run lint:js
npm run lint:css
npm run format
npm run zip
```

`npm start`, `npm run build`, linting, formatting, and ZIP creation use
`@wordpress/scripts`. PHP feature discovery runs inside WordPress and is not
generated by npm. The custom webpack configuration discovers JavaScript and
SCSS entries below `src/`, preserves their semantic paths, and removes empty
JavaScript files emitted for standalone SCSS entries.

## Version

`package.json` is the single version source. Use npm so `package.json` and
`package-lock.json` stay synchronized, then run the production build:

```bash
npm version 0.2.0 --no-git-tag-version
npm run build
```

The build copies that version into the WordPress plugin header and
`WITH_SITE_TOOLS_VERSION` in `with-site-tools.php`. Replace `0.2.0` with the
intended release version. `npm version patch|minor|major --no-git-tag-version`
can be used for semantic increments.

The production build writes compiled JavaScript and CSS exclusively to
`build/`. Each feature's PHP stays in its single `src/**/index.php` entrypoint
and is not copied through webpack.

## wp-env

```bash
npm run env:start
npm run env:stop
npm run env:clean
```

`env:start` uses `--auto-port`. `.wp-env.json` mounts the repository root as the
plugin, tests the declared PHP 8.0 minimum, and enables WordPress debug logging
and unminified scripts.

## PHP checks

PHP files use PHP 8.0 strict types and are written against WordPress Coding
Standards. PHP syntax is checked directly with `php -l`. Automated WPCS
compliance is not claimed until a PHP_CodeSniffer toolchain is deliberately
approved and added.
